## Procedure

1. Created a temporary Git repository with one tracked `src/app.js` and one commit.
2. Ran:

   ```bash
   node skills/methodrail-init/scripts/linked-harness.mjs create \
     --repo /absolute/path/to/disposable-app \
     --storage /absolute/path/to/disposable-app-methodrail
   ```

3. Wrote a valid typed note and PROJECT.md pointer through the repository-root `.methodrail` link.
4. Evaluated the disposable root with `evaluateProjectKnowledge` / `evaluateFreshness` via `npx tsx`.
5. Mutated `src/app.js` and rechecked freshness.
6. Reran create without `--storage`.
7. Exercised failure modes one at a time, then restored a valid binding and ran create twice.

## Limitations

- Windows junction behavior was **not** exercised. Do not claim cross-platform verification from this run.
- The disposable repository lived under `/tmp` only. Absolute temporary paths and external knowledge were not committed.
- First attempt at the “remove exclude” failure used a relative exclude path from the Methodrail cwd and briefly wrote Methodrail’s local exclude. That was corrected: Methodrail’s `.git/info/exclude` was restored to the stock Git template, and the failure was re-run against the disposable repository with an absolute exclude path.

## Conclusion

Linked-external placement on Darwin works for create, ignore, knowledge validation, freshness against the repository root, idempotent re-create, and the fail-closed diagnostics listed above. Ready for v0.7.1 release metadata after human review of the release diff.
