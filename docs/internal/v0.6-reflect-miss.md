Internal maintainer record from dogfooding. Not a public architecture document.

## Miss

Copied `evals/fixtures/simple-change/repo` to `/tmp/methodrail-miss-simple` and solved "Change Save to Create" as a generic agent with no Methodrail skills.

Unconstrained path:

1. `wayfinder` to map the tiny repo

Over-escalation is still refused by a synthetic `scoreRun` test, not by rewriting the recorded baseline. `evals/complexity/button-text.yaml` already forbids the same operators. Did not add `evals/complexity/simple-label.yaml`.

## Classification

```text
structural-enforcement problem
```

Not a knowledge problem: no missing project fact. The string is in `src/button.js`.

Not a skill problem: `develop` already says tiny changes are inspect → edit → deterministic check, and not to auto-invoke `wayfinder` / `architect` / `interrogate` for routine work. `how` and `rules/methodrail.mdc` already ask for proportional depth. Another reminder paragraph would restate existing guidance.

Not a verification problem as the primary miss: the baseline skipped the cheap check, but the distinctive failure is unnecessary expensive operators, not a missing test harness.

Not a tooling problem: read, edit, and the fixture's `npm test` were available.

This is a structural-enforcement problem: a compiler-like check on recorded traces can refuse over-escalation more reliably than skill prose. Reflect routes anything a mechanical check would enforce onto the structural-enforcement list. Prefer a stronger check, test, type, or fixture over another paragraph.

## Why a test, not a paragraph

v0.6 hard rule: do not add a new paragraph to `skills/how`, `skills/develop`, or `rules/methodrail.mdc` to remind agents not to over-escalate.

Skill prose is already present and did not bind the unconstrained agent. `scoreRun` plus the simple-change fixture can fail traces that invoke forbidden skills, exceed `max_subagents` / `max_expensive_skills`, or (for recorded Methodrail traces) omit verification. That is a test, not a conversation reminder.
