# v0.7 Verified Knowledge Reuse

Internal product note. Baseline: `46050c3921b0a396da861184cd01f0f1718435ae` (`feat: v0.6.1`).

v0.7.0 is Harness Intelligence’s first vertical slice. Methodrail can promote evidence-backed project knowledge, index it for later sessions, validate provenance, check freshness against relevant paths, and reuse or reconcile it. It is not a memory service.

## Behavior

```text
real work discovers expensive knowledge
→ a human approves it
→ Methodrail records one typed note plus one PROJECT.md pointer
→ a fresh-session agent finds the pointer
→ the agent checks freshness on relevant_paths
→ the agent reuses or reconciles
```

Typed notes live under `.methodrail/knowledge/<slug>.md`. Identity is the path. Decisions stay in `.methodrail/knowledge/decisions/` on the existing decision template.

## Kinds and status

Closed typed kinds: `fact`, `invariant`, `convention`, `known-failure`, `hypothesis`.

`rationale` and `observation` remain records, not typed notes.

Status: `verified` (meaningful evidence required) or `provisional`. A `hypothesis` must be `provisional`.

`validated_at` is a 40-character Git SHA, or `unversioned:<reason>` when there is no Git history. Short or ambiguous SHAs are invalid as provenance and never count as fresh.

## Init is lazy

Initialization recognizes typed and legacy notes, checks the PROJECT.md index, and reports freshness warnings. It does not create typed notes. Promotion is Reflect after real work, with explicit human approval.

## Consumer vs maintainer

TypeScript in this repository validates Methodrail and its fixtures. Consuming projects follow skills and the shared reuse procedure. There is no consumer daemon, database, or Methodrail CLI.

Structural validation failures (unknown kind, missing evidence on a verified note, missing index pointer, path traversal, oversized note, duplicate identity/title) fail `npm run validate`. Freshness states `review-required` and `unknown` are warnings, not repository-invalid.

## Non-goals

- Memory database, embeddings, vector search, or an external retrieval service
- A file watcher or automatic full-repository invalidation
- Automatic transcript harvesting or silent promotion
- A persistent candidate queue
- A new public skill
- Rewriting T6 / T8 / T9 history to make v0.7 look favorable
