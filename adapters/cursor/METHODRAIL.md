# Methodrail (progressive index)

Load this file when you need the catalog. Do not keep the full skill texts in context.

## Workflows

- `debug`: Reproduce, explain, and minimally fix a failure without symptom-to-patch guessing.
- `develop`: Turn sufficiently resolved intent into bounded implementation with evidence.
- `investigate`: Answer a question about an existing system without prematurely changing it.
- `refactor`: Improve internal structure without accidentally changing external behavior.
- `review`: Review a prepared change using a ReviewPacket and a convergence policy.

## Skills

- `architect` (architecture, rigor ≥ 3): Compare architectural shapes for a consequential design decision.
- `blast-radius` (investigation, rigor ≥ 2): Understand what else a proposed or completed change may affect.
- `create-control-adapter` (adapter, rigor ≥ 1): Build a project-local interface so generic skills can operate the real system.
- `domain-modeling` (modeling, rigor ≥ 2): Create precise language and capture domain invariants.
- `how` (investigation, rigor ≥ 1): Understand how a current system or subsystem works.
- `interrogate` (review, rigor ≥ 4): High-rigor adversarial review when cost and risk justify it.
- `maintain-control-adapter` (adapter, rigor ≥ 1): Detect and repair drift in project-local control infrastructure.
- `observe` (observation, rigor ≥ 2): Determine what the running system actually does.
- `prototype` (experiment, rigor ≥ 2): Answer an empirical question with a disposable experiment.
- `review` (review, rigor ≥ 2): Perform bounded implementation review against a prepared packet.
- `systematic-debugging` (debugging, rigor ≥ 2): Prevent symptom-to-fix guessing.
- `verify-change` (verification, rigor ≥ 0): Block unsupported completion claims.
- `why` (investigation, rigor ≥ 1): Investigate historical motivation without inventing intent.
