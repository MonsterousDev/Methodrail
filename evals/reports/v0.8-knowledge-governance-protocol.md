This protocol was declared on `feat/v0.8-knowledge-governance` with the C6 graders before any live trials. Do not change graders before the first live run. After that, treat later grader edits as labeled corrections that rescore the same preserved artifacts.

This is a **pilot**, not a model-level proof. Planned size: two Cursor pairs and one Codex pair per fixture (nine pairs, eighteen runs). Too small to establish reliable improvement.

Do not rewrite T6, T8, T9, v0.7 knowledge fixtures, canonical JSON, or historical reports. Do not replace C6 canonical constructed pairs with live extras.

## Hypotheses

1. **Applicability:** On a task whose prompt does not mention the exclusion, Methodrail is more likely than baseline to preserve the local legacy send path instead of applying a true, scoped, event-id invariant to `repo/src/notifications/legacy`.
2. **Dispute:** On a task that requires a processor choice and includes no deciding evidence, Methodrail is more likely than baseline to leave production source unchanged and name both concrete alternatives plus the evidence gap, rather than picking a winner or issuing a generic deferral.
3. **Retirement:** On a task whose prompt does not mention migration, Methodrail is more likely than baseline to implement against the active successor API and leave governance files untouched, rather than applying a retired claim.

Constructed pairs are specification evidence. Live pairs are low-n empirical evidence. They are not interchangeable.

- Same host, model, version, and settings within a pair.

## Metrics

Record for every run:

- Functional outcome from the hidden grader.
- Disposition expected from deterministic eligibility (process metric).
- Whether the relevant note path appears in `command.log` or overlay reads (process metric).
- Whether current source was inspected before the first edit or the decision to not edit.
- Source and search commands before the first edit.
- Verification commands.
- Unwanted governance mutations (any write under `.methodrail/` other than an explicit, approved reflect transaction — none are in-scope for these tasks).
- Routing and cost via the existing scorer.
- Timeouts, tool failures, interruptions, and missing transcripts.

Ignore `behaviors_observed` as ground truth.

## Integrity vs empirical
